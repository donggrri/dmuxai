## 1. Decision summary

The dashboard center column (`main`) was a fixed `max-width: 880px` column centered with `margin: 0 auto`. On a wide screen the chat, the graph swimlane and the task checklist used less than half the window. The Documents panel ("Changed by agents") was always open and pushed the graph down.

Decision: `main` fills the whole content area between the docked sidebars (no width cap). The docked-sidebar padding from SPEC-centered-prompt stays, so a docked sidebar still never covers the column, and the prompt box, which now spans the column, stays centered in the content area. The chat transcript grows with the viewport height. The Documents panel gets a header button that expands and collapses it; it is collapsed on every new page load unless the user expanded it earlier in the same browser session.

The chat panel is laid out like ChatGPT: it fills the viewport height below the header, the transcript scrolls on its own, the composer is a rounded box pinned at the bottom with Send inside it, user turns are right-aligned bubbles, agent turns are plain left-aligned text with styled code blocks, and messages plus composer share one centered column of about 860px while the panel background spans the full width.

Duplication found: every agent turn's change record (`TurnChanges.output_tail`, FR-748) is the last 40 lines of the same chat message the transcript shows (`last_agent_output_text`), and the Documents panel printed it as `pre.doc-tail`. So each reply appeared twice, once in the chat and once in Documents. The record now carries `message_id`, the `SessionMessage.id` of that chat message. When that message is in the chat, the reply is rendered there only: Documents keeps the files plus a one-line reference with "Show in chat", and the chat message gets a compact document card (file name, kind, one-line change summary, "Open in Documents"). Turns whose message is not in the chat (graph nodes, other conversations, capped transcript) still show their tail in Documents.

Diff and Graph are not inline any more. The dashboard has no separate diff viewer; the "Diff" is the agents' change list (the Documents panel above: changed files, change kind, open/preview). Both the Diff view and the Graph view (swimlane, plan approval, task checklist, node list) open from header buttons next to To-dos and cover the center area between the docked sidebars, so the graph keeps the full width. Chat stays the center view underneath. A plan that waits for approval opens the Graph view once, and the chat always carries an inline approval card (Approve / Edit / Reject / Open graph) until the plan is decided.

The agent's processing shows inline in the chat, like the Grok Bot app: compact, muted, one-line rows that expand on click. While a run is active a status row ("Running step-1 on grok · 0/1 steps · 2s") sits under the exchange; expanding it lists the steps with status icons, and a step opens the Graph view focused on that node. Consecutive tool activity lines of a turn fold into one "N actions · last action" row. The document card lists each changed file (Created / Edited / Deleted + path), and a file row opens Diff at that file. Only data the dashboard already receives is used: `graph.nodes` (status, runner, times), `graph.phase`, `graph.approval`, `agents[].run` and `agents[].activity`, the transcript's `activity` messages, and the change log. The change log has no line counts, so the "+N/−M" part of a file row is not shown (skipped, not invented).

Graphs follow the conversation. Before, opening or switching to a conversation cleared the retained graph (FR-525/FR-530), so the Graph view stayed empty until a new run, even though every run is stored in `.dmuxai/graphs/` with its `conversation_id`. Now the opened conversation's latest stored run is loaded as read-only history (never another conversation's; a live run of the conversation still wins; a run left mid-run is shown as cancelled and never resumed; a stored awaiting plan keeps the FR-942 stale rule). Each chat exchange that started a run gets its own collapsed run row, linked through the turn bands (`graph.turns[]`, now with `message_id` and per-step status), and an older run opens in the Graph view through a new `show_graph_run` command.

## 2. Scope

In scope: the header (`Diff`, `Graph` buttons), `src/web/assets/index.html`, `app.css`, `session.css`, `session.js`, `docs.css`, `docs.js`, `app.js` (graph re-layout on column width changes), and `TurnChanges.message_id` (`src/docs/changes.rs`, `src/app.rs`). Out of scope: the TUI, the Files tree in the right sidebar, the document preview overlay, and the Agents and Memory panels, which stay inline.

## 3. Terms

- Content area: the viewport minus each open docked sidebar (above 900px). At 900px and below the sidebars are overlay drawers and the content area is the viewport.
- Documents panel: `<section id="docs">`, the center panel titled "Documents" that lists the files each agent turn changed (SPEC-docs-preview FR-748).
