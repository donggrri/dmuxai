## 1. Decision summary

DmuxAI enables graph engineering by default for every user prompt, automatically synthesizing execution plans through the planner while treating trivial prompts as single-node graphs. Users can opt out globally by configuring `[graph] enabled = false` in `dmuxai.toml`. When a graph run is in progress, DmuxAI displays a compact live status line above the prompt input showing current node id, runner, model, execution state (`pending`, `running`, `done`, `failed`), and overall progress `n/m` (e.g. `"Graph 2/4 · step-2 implement · agy gemini-3.8-flash-medium · running"`). When no graph is active, this line is hidden. Model resolution guarantees that an F2-selected model for a runner always wins, while the default `composer-2.5` model applies strictly to the Cursor runner.

## 2. Scope

### In scope

- Graph engineering on by default (`settings.graph_enabled = true`) for all prompt submissions.
- Configuration toggle via `[graph] enabled = false` in `dmuxai.toml` to disable graph planning.
- Automatic planner distinction: multi-step DAG plans for complex work; single-node execution plans for trivial prompts.
- Compact live status line rendered directly above the prompt input area during active graph execution.
- Real-time status reporting: current node id, role/description, runner and effective model, execution state (`pending`, `running`, `done`, `failed`), and progress count `n/m`.
- Automatic hiding of the graph status line when no graph is running or when graph mode is disabled.
- Model selection precedence: user selection via F2 wins; `composer-2.5` default applies only to Cursor; other runners fall back to provider default.

### Out of scope / non-goals

- Graphical DAG visualization canvas or interactive visual flowchart editor.
- Multiple terminal multiplexer splits or tmux panes (logical concurrent nodes only).
- Dynamic restructuring of DAG edge dependencies mid-flight without explicit user command.
- Overriding provider CLI internal rate-limiting or token quotas.

## 3. Terms and state model

| Term | Meaning | Not to be confused with |
| --- | --- | --- |
| Graph plan | Multi-node or single-node execution plan generated by `plan_request`. | Conversation turn snapshot. |
| Graph status line | Live 1-line TUI status indicator placed above the prompt input area. | Bottom status bar (active agent, mode, effort, key hints). |
| Effective model | Resolved model ID for a node, prioritizing F2 model picker over defaults. | Planned default model ID. |
| Node state | Execution status of an individual graph node: `pending`, `running`, `done`, `failed`. | Overall app busy state. |

### Node state transitions

```text
[ Pending ] ---> [ Running ] ---> [ Done ] ---> (Next node or Complete)
                      |
                      +---------> [ Failed ]
                      |
                      +---------> [ Paused / Gate ] ---> [ Running ] (via /graph continue)
```

## 6. Data, integration, and safety contracts

| Area | Contract / change | Compatibility and rollback | Evidence |
| --- | --- | --- | --- |
| Configuration | `[graph] enabled = bool` supported in `dmuxai.toml`; defaults to `true`. | Missing `[graph]` block defaults to enabled; setting `false` cleanly disables graph mode. | TC-370 |
| Model Policy | F2 user selection takes precedence; `composer-2.5` restricted to `cursor`. Non-cursor runners default to provider default. | Prevents sending Cursor-specific model ids to external providers (e.g. AGY, Codex). | TC-372 |
| UI Layout | Dynamic 1-line constraint above prompt input area when graph is active; 0-height when inactive. | Preserves chat scrolling and terminal layout stability across all window sizes. | TC-373 |
| State Formatting | Status line string formatted deterministically: `"Graph {n}/{m} · {node_id} {role} · {runner} {model} · {state}"`. | Safe Unicode truncation ensures no layout overflow or line wrapping. | TC-373, TC-374 |
